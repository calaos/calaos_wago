# T-6 — la relecture DALI ignore le drapeau groupe sur un chemin et l'honore sur l'autre

**Statut** : 📋 · **Type** : fix

---

## 1. Ce n'est pas « une variable inutilisée »

Une première lecture rapide conclut que `dali_group`, calculé dans le gestionnaire
`WAGO_DALI_GET` (`src/targets/881/UDPSERVER.EXP:255-259`), n'est jamais employé. **C'est faux** : il
l'est, mais **seulement sur l'un des deux chemins de relecture**.

`WAGO_DALI_GET` ne fait que déclencher la lecture ; la réponse est construite plus bas, dans le bloc
`IF (DaliSend = TRUE)` (`UDPSERVER.EXP:550-599`), et ce bloc se scinde en deux :

| chemin | condition | `dali_group` |
|---|---|---|
| DALI standard (753-641) | `Config.CONFIG_DALI = TRUE`, l.563-573 | ⛔ **ignoré** |
| DALI multi-maître (753-647) | `ELSE`, l.574-596 | ✔ **honoré** |

Le chemin 647 choisit bien son tableau selon le drapeau (`UDPSERVER.EXP:576-592`) :

```pascal
IF dali_group = TRUE THEN
    ... DaliSendValueGrp647[daliShortAddr].rActualLevel ...
ELSE
    ... DaliSendValue647[daliShortAddr].rActualLevel ...
END_IF
```

Le chemin `CONFIG_DALI`, lui, appelle `DALIDimmValue` avec la seule adresse courte
(`UDPSERVER.EXP:264` et `:572`) :

```pascal
DALIDimmValue(xEnable := TRUE, bShortAddress := DINT_TO_BYTE(p2), tCycleTime := t#1s);
```

⇒ sur une installation en DALI standard, **une relecture de groupe renvoie le niveau de l'adresse
courte de même numéro**. Demander le groupe 3 répond pour la lampe d'adresse courte 3.

## 2. Le bloc fonctionnel appelé ne sait pas ce qu'est un groupe

Ce n'est pas un paramètre oublié à l'appel : `DaliDimValue`
(`src/common/DALIDIMVALUE.EXP:6-18`) n'a **aucune entrée de groupe** dans son interface —
`bShortAddress`, `tCycleTime`, `bModule_750_641`, et rien d'autre. En interne il passe à
`FbDALI_StatusDimmValue` la seule adresse courte (l.30-40), et la branche 647 indexe
`arActualValue[bShortAddress - 1]` (l.44), un tableau par adresse.

⇒ corriger l'appel ne suffit pas : il faut **étendre `DaliDimValue`** pour qu'il porte la notion de
groupe, ou router la relecture de groupe vers un autre bloc fonctionnel.

## 3. L'asymétrie est réelle : on pilote un groupe, on ne peut pas le relire

`WAGO_DALI_SET` sait parfaitement adresser un groupe — il transmet le drapeau à `Dali_switch`
(`UDPSERVER.EXP:244-245`) :

```pascal
Dali_switch(bAddress := DINT_TO_BYTE(p3), xGroup := dali_group, ...);
```

Et le type `TELERUPTEUR_DALI_GROUP` existe dans `output_type` (`UDPSERVER.EXP:104`, `:132`). La
capacité groupe est donc bien dans le produit ; c'est la **relecture en DALI standard** qui ne suit
pas.

## 4. Acceptation

1. Une relecture de groupe en DALI standard renvoie l'état du **groupe**, pas d'une adresse courte
   homonyme — ou, si le matériel ne le permet pas, elle répond une erreur explicite au lieu d'une
   valeur fausse.
2. ⭐ Les deux chemins de relecture donnent la **même** réponse à la même question. Tant qu'ils
   divergent, le comportement dépend d'un réglage d'installation que l'appelant ne connaît pas.

## 5. ⚠️ Au voisinage, non instruit : l'adresse courte 0

`DALIDIMVALUE.EXP:44` indexe `arActualValue[bShortAddress - 1]` sur un `ARRAY[0..96] OF REAL`. Une
adresse courte DALI valide commence à **0**. En arithmétique `BYTE`, `0 - 1` vaut 255 → index 255
hors bornes, corruption muette.

⛔ **Non vérifié** : on ne sait pas si ce chemin reçoit des adresses 0-basées ou 1-basées. Le tableau
voisin `axShortAddress: ARRAY[0..63] OF BOOL` (l.23) suggère 0..63, ce qui rendrait le `- 1` faux,
mais `arActualValue` est alimenté par la bibliothèque WAGO dont le source n'est pas dans le dépôt.
**À instruire avant d'y toucher** — c'est peut-être une convention 1-basée parfaitement volontaire.

## 6. ⛔ Le nu

Lu, compilé, jamais exécuté. Le source vient des `.exp` exportés du `.pro`, pas d'un `strings` :
texte et numéros de ligne fiables. Le partage en deux chemins et l'usage de `dali_group` sont **lus
dans le code**, y compris l'imbrication des `IF` du bloc `DaliSend`, qui est courte et sans
ambiguïté ici. En revanche le **comportement observable** — « demander le groupe 3 répond pour
l'adresse 3 » — est **déduit** de la signature de `DaliDimValue`, pas mesuré : personne n'a
interrogé un groupe sur un banc DALI. Le contenu réel de `FbDALI_StatusDimmValue` est inconnu, la
bibliothèque étant livrée compressée.
