# T-4 — 16 sorties de la carte Modbus ne sont jamais relues par l'automate

**Statut** : 📋 · **Type** : fix

---

## 1. La zone déclarée fait 256 coils, la boucle n'en lit que 240

`src/targets/881/VARIABLES_GLOBALES.EXP:68` (identique sur les 7 cibles) :

```pascal
netOutStandard AT %IB512: ARRAY[0..31] OF BYTE;
```

32 octets = **256 bits**, ce qui concorde avec la cartographie écrite juste au-dessus
(`VARIABLES_GLOBALES.EXP:60-66`) :

```
Modbus addresses mapping:
    - [4096..4352] : Standard digital outputs
```

Mais la branche mode serveur de `PLC_PRG` (`src/targets/881/PLC_PRG.EXP:68-74`) est bornée à 15
tours :

```pascal
j := 0;
FOR i := 0 TO 14 DO
    valw := netOutStandard[j + 1];
    write_word(WORD_ADDRESS := i + start_addr_out / 16, VALUE := SHL(valw, 8) + netOutStandard[j]);
    OutArrState[start_addr_out / 8 + j] := netOutStandard[j];
    OutArrState[start_addr_out / 8 + j + 1] := netOutStandard[j + 1];
    j := j + 2;
END_FOR
```

`j` prend 0, 2, … 28 : la boucle lit `netOutStandard[0..29]`, soit **30 octets sur 32**.

⇒ `netOutStandard[30..31]`, c'est-à-dire les **coils 4336..4351**, ne sont **jamais** lues. Ni
publiées sur les sorties physiques, ni recopiées dans `OutArrState`. Ce que `calaos_server` y écrit
tombe dans le vide, en mode serveur comme en mode dégradé.

## 2. Ce n'est pas le même défaut que T-2

T-2 corrigeait *où* le miroir écrivait ; celui-ci porte sur *jusqu'où* la boucle lit. Les deux
cohabitent dans les mêmes trois lignes et le correctif T-2 n'y change rien : la borne `TO 14` est
antérieure et intacte.

## 3. Piste de correctif

`FOR i := 0 TO 15` suffirait à couvrir les 32 octets. Vérifications déjà faites sur les bornes,
aucune ne bloque :

- `write_word(WORD_ADDRESS := 15 + start_addr_out / 16)` → mot 15 sans borne 647
  (`start_addr_out = 0`), mot 27 avec une borne 753-647 (`start_addr_out = 192`).
- `OutArrState[start_addr_out / 8 + 31]` → index 31 sans 647, 55 avec ; le tableau est un
  `ARRAY[0..512]` (`VARIABLES_GLOBALES.EXP:34`). Large marge.
- La boucle du mode dégradé (`PLC_PRG.EXP:59-64`) couvre déjà `FOR i := start_addr_out / 16 TO 255`,
  donc toute la plage : elle n'a pas besoin d'être touchée.

⚠️ Cela modifie la ligne `write_word` de la branche serveur, que la fiche T-2 §6 ter déclare
**correcte**. Elle l'est pour ce qu'elle écrit ; c'est le nombre de tours qui est en cause, pas le
calcul d'adresse. À relire avant d'appliquer.

## 4. ⛔ Ce qui décide de l'importance, et qui n'est pas dans ce dépôt

On ne sait pas, depuis `calaos_wago`, si `calaos_server` écrit réellement au-delà de la coil 4335.
La réponse est dans `calaos_base` (`Constants.h`, `WODigital.cpp`, `WagoCtrl.cpp`), hors de ce
dépôt. Si le serveur ne dépasse jamais 240 sorties, le défaut est latent — une réserve annoncée mais
inexploitable. S'il les dépasse, 16 sorties sont silencieusement mortes.

⇒ **Vérifier cela avant de coder.** C'est la seule question ouverte du dossier.

## 5. ⛔ Le nu

Lu, compilé, jamais exécuté sur automate. Les déclarations et la boucle sont lues dans le source
`.exp` exporté du `.pro` — pas dans un binaire passé au `strings`, donc le texte est fiable et les
numéros de ligne aussi. Le décompte 15 tours → 30 octets → coils 4336..4351 est de l'arithmétique
sur ce texte, pas une mesure. **Aucune trame Modbus n'a été observée**, et personne n'a vérifié sur
un rack qu'une sortie au-delà de la 240e reste morte.
